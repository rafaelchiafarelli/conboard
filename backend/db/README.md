# conboard rules database (SQLite)

The persisted **rules/actions library** — the source of truth for *authoring* and
*portability*, **not** the realtime execution path (hardware runs from `boards/*.json`).
See the project memory `conboard-rules-db-architecture`.

## What it is
A single embedded **SQLite** file (`CONBOARD_DB`, default `/conboard/backend/data/
conboard.db`). No server, no daemon — just the file plus the bundled `libsqlite3.so`.
Chosen because the library is device-local, single-writer and authoring-only, and must
run on boards without Docker or an apt step.

## Schema
Generated by harpia from `../harpia/conboard.harpia` and emitted under
[`../generated/database/`](../generated/database/) (the SQLite DDL). It is **not**
applied from a migration file: the backend creates every table (and its child link
tables) at boot via the generated DAO `create_table()` (idempotent, `CREATE TABLE IF
NOT EXISTS`). To inspect the DDL, read `../generated/database/*.sql`.

Entities (see `../harpia/README.md`): `board` / `mode` / `rule` / `trigger` /
`output_action`. **copy A→B** duplicates a board's rows re-keyed to board B (PKs are
caller-assigned).

## Config
`backend.env.example` — runtime env template (copy → `.env`, gitignored).

> A central **PostgreSQL** authoring host is available later via
> `HARPIA_DB_BACKEND=postgresql backend/generate.sh` — the C++ API is identical. Not
> used on-device.
